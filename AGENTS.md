# Codex Operating Instructions

This repository contains the durable implementation home for **LOOP ENGINEERING ∞ + × PARALLEL AGENTS™**.

## Mission

Operate toward the long-horizon objective in `loop-engineering/GOAL.md`. Preserve all valid lineage, make changes on dedicated branches, run tests before proposing release, and leave auditable evidence for every material claim.

## Non-negotiable rules

1. Truth before appearance, speed, or persuasion.
2. Evidence before proof claims.
3. Preservation before replacement.
4. Additive improvement by default.
5. Use parallel workstreams only when they add distinct value.
6. Never claim independent verification when workstreams share material dependencies.
7. Never claim battle-tested, proven, validated, or 1,000/1,000-calibre status without the required evidence and a completed Proof Envelope.
8. Keep human approval gates for legal, financial, regulated, irreversible, safety-sensitive, security-sensitive, or public-facing actions.
9. Do not publish, contact third parties, spend money, create legal commitments, or expose confidential information without explicit approval.
10. Prefer refining an existing asset over creating a new named asset unless the new function is genuinely distinct and governable.

## Standard execution loop

Sense → Interpret → Align → Prioritize → Specify → Map → Diversify → Simulate → Parallelize → Execute → Observe → Verify → Challenge → Secure → Reconcile → Decide → Release → Communicate → Monitor → Respond → Recover → Diagnose → Learn → Calibrate → Codify → Integrate → Realize → Multiply → Renew → Retire → Discover → Re-enter ∞

## Required evidence for material changes

- change rationale
- affected assets and dependencies
- tests run and results
- known limitations
- rollback path
- proof maturity before and after
- updated registry entries

## Canonical source of truth

The machine-readable registry under `loop-engineering/registry/` is authoritative for names, identifiers, versions, counts, owners, maturity, dependencies, and review dates. Narrative documents must not silently diverge from it.

## Delivery standard

Prefer complete working implementations, tests, and documentation over conceptual expansion. Stop only when the goal’s stopping conditions are met or an external dependency genuinely requires human action.
